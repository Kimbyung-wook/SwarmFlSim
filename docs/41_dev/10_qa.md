# 10. QA 하니스

실제 프로세스를 띄워 전체 경로를 시험하는 도구가 [qa/](../../qa/)에 있다. 시험 설명, 판정 기준, 결과는 [21_qa_report.md](../21_qa_report.md)에 있다.

## 10.1 실행

먼저 C++ 빌드와 `uv sync`를 끝낸다.

```bash
uv run --with psutil python qa/run_qa.py --list
```

```bash
uv run --with psutil python qa/run_qa.py --only 001,010
```

| 옵션 | 뜻 |
|---|---|
| `--list` | 시험 목록 |
| `--only <번호,...>` | 일부만 실행. 없으면 전체 |
| `--build-dir <dir>` | C++ 빌드 디렉터리 |

결과는 `qa/out/<TC>/`(프로세스 로그, MCAP, `.pb`)와 `qa/out/results.json`에 남는다.

## 10.2 시험 구성

| 묶음 | 내용 |
|---|---|
| s1~s5 | 편대, 군집 다중 임무, 불완전 링크, 표적·장비 선언, 혼합 모델 |
| s6 | 부하 50대·100대, lockstep과 realtime |
| 통제 | 일시정지·재개·스텝·배속·리셋, 모드 전환, 잘못된 `SimCommand` |
| 임무 명령 | 정상 경로, 연속·충돌 명령, 잘못된 값 |

시나리오는 [qa/scenarios/](../../qa/scenarios/)에 있고 `qa_s*`, `qa_p5_*`, `qa_los_*`, `qa_dem_*`, `gw_*`처럼 목적별 접두어를 쓴다. `qa_agra28.json`은 승인·탐지 공유를 켠 A-GRA 교환 시연용이다(QA 28차). 프로세스 묶음과 관측기는 [qa/harness.py](../../qa/harness.py)의 `Stack`, `Observer`다.

## 10.3 결정성 진단

같은 시나리오를 lockstep으로 여러 번 돌려 궤적 차이를 본다.

```bash
uv run python qa/diag_determinism.py --frames 3000 --seed 7 --runs 2
```

| 옵션 | 뜻 |
|---|---|
| `--scenario <file>` | 대상 시나리오 |
| `--frames`, `--seed`, `--runs` | 프레임 수, 시드, 반복 횟수 |
| `--verbose` | 자세한 출력 |

lockstep에 영향을 주는 변경은 이 진단으로 확인한다([9장](09_contributing.md)).

`LinkOutcome`과 GCS 수신까지 비교할 때는 `qa/gw_plan.py --lockstep-det`를 쓴다. 같은 시드 lockstep을 반복해 앞 60 s를 1번 실행과 비교한다.

```bash
uv run python qa/gw_plan.py --lockstep-det qa/out/det --det-runs 8 --variants noloss,loss,fault_noloss,fault_loss,payload
```

## 10.4 고장 주입

실행 중인 버스에 고장을 넣는다. 종류와 효과는 사용자 매뉴얼 [7.4](../42_user/07_link.md#74-고장-주입).

```bash
uv run python qa/inject_fault.py --connect tcp/127.0.0.1:17601 --entity uav-003 --kind LINK_CUT --duration 10
```

## 10.5 성능 측정

P1 성능 조건은 3-DoF 100대 waypoint, lockstep 최대 배속(`--rate 0`), Logger 켬, Agent 1개에서 10배 이상이다(DEC-082, DEC-084). P1은 이 조건으로 완료 판정했다(DEC-087, 12.43배). 측정 도구는 `qa/perf_p1.py`(실스택 배속·프레임 분해, Logger 켬·Agent 분할·`--state-period 0`·Agent 계측 구성)와 `qa/perf_agent.py`(Agent 단독 비용)이고 결과는 `qa/out/perf/`(git 제외)에 쌓인다. 측정 조건과 결과는 [21_qa_report.md §29·§31~§34](../21_qa_report.md#34-26차-측정-p1-판정-재측정-dec-086-개선-뒤-2026-11-15)에 있다.

### 판정 방식 (DEC-086(2))

성능 판정과 성능 회귀 판정은 다음 방식으로 한다(DEC-087에서 계속 쓰기로 했다).

| 항목 | 방식 |
|---|---|
| 창 | 긴 창(판정 구성은 7,500 프레임). 짧은 창은 참고값으로만 쓴다 |
| 묶음 | 서로 다른 시간대 2묶음. 26차는 1시간을 쉬고 두 번째 묶음을 쟀다 |
| 대표값 | 6회 이상 중앙값 |
| 짝 값 | 같은 실행의 Logger 끔 값을 함께 기록한다. Logger 비용은 같은 회차·같은 스케줄링의 Logger 켬 − 끔이다 |
| 회차 기록 | 회차 값과 E 코어 배치 표시를 같이 남긴다. 시스템 CPU의 40% 넘게가 논리 코어 16~31에 있었던 회차가 E 코어 회차다(O-42) |
| 교차 확인 | P 코어 고정 구성을 같이 잰다 |
| 빌드 | release, `-DSWARM_REQUIRE_ZENOH=ON`([2.2](02_build_test.md#22-c-core-동역학-datalink-logger-payload-버스)) |

- 같은 구성도 시간대에 따라 17%까지 달라졌다(O-40). 한 번 실행으로 판정하지 않는다. E 코어 회차는 3.9~7.9배까지 떨어졌다.
- 다른 측정이 도는 PC에서는 시뮬레이터를 띄우지 않는다. 26차는 단계마다 다른 worktree의 시뮬레이터 프로세스가 30 s 동안 없음을 확인했다.

### Agent 틱 계측 (IMP-AGT-042)

Agent가 어디에 시간을 쓰는지 볼 때 `swarm-agent --profile <파일>`을 주거나 환경 변수 `SWARM_AGENT_PROFILE=<파일>`을 둔다. 기본은 꺼져 있고, 켜도 버스 출력은 바이트 단위로 같다(TC-AGT-128).

- 틱 처리 단계(MA, FA, 활동 보고, 제어 발행, FrameDone 등)와 틱 사이 입력 처리(키 종류별)를 벽시계로 잰다.
- 프레임 위상(`frame % 50`, 1 Hz 주기 안의 자리)별로 더한다. 앞 250틱은 버린다.
- 결과는 JSON이고 500틱마다와 닫을 때 덮어쓴다. 프로세스를 강제로 끝내도 남는다. `summary`에 위상 0·위상 4·나머지·전체의 프레임당 ms가 있다.
- `qa/perf_p1.py`의 계측 구성은 결과를 `agent-N_profile.json`으로 남긴다. 26차 분해 결과는 [QA §34.5](../21_qa_report.md#34-26차-측정-p1-판정-재측정-dec-086-개선-뒤-2026-11-15)에 있다.

## 10.7 표준 적합성 점검

UCI·A-GRA·OMS/LA-CAL·AMS-GRA 적용을 자체 도구 [qa/conformance/](../../qa/conformance/)로 점검한다(DEC-092). 공식 적합성 시험을 대신하지 않는다.

| 문서 | 내용 |
|---|---|
| [44_standards_conformance.md](../44_standards_conformance.md) | 점검 기준 C1~C7, 한계(§4), 도구 사용(§5), 이력 규칙(§6) |
| [45_standards_report.md](../45_standards_report.md) | 도구가 만든 최근 보고서 |
| [46_amsgra_applicability.md](../46_amsgra_applicability.md) | AMS-GRA 요구별 적용성(해당·부분·해당없음과 근거, DEC-093) |
| [47_conformance_history.md](../47_conformance_history.md) | 실행 이력, 점검 조건 변경 이력, 발견 추적(해소 원인 포함) |

- 점검 전에 msvc-release Core를 빌드한다. 계약 proto가 바뀌었으면 `scripts/gen_proto.py`로 생성 코드를 다시 만든다([44 §5](../44_standards_conformance.md#5-도구-사용)).
- 실행할 때마다 `qa/conformance/history.jsonl`에 한 줄이 붙고, 도구가 이를 읽어 `docs/47`을 만든다. 두 파일 모두 손으로 고치지 않는다(DEC-095).
- 판정이 바뀌었으면 `docs/47`의 점검 조건 변경 이력으로 원인이 기준·도구 변경인지 제품 변경인지 가른다.
- C1은 기체 안에서만 오가는 STD 메시지를 "Gateway 범위 밖(기체 내부)"으로 표시하고 실패로 보지 않는다(DEC-094). C5의 외부 명령 상태는 UCI Command-2 상태 기계로 판정한다(DEC-097).
- 2026-11-20 33차 점검(계약 0.20.0)은 C1~C6 통과, C7 정보다. C3에 UCI 시각 기준(DEC-098) 대조가 들어 있다.
- A-GRA L1의 DDS 요구는 점검 한계로 둔다. 미들웨어 변경은 보류했다(DEC-099, [44 §4](../44_standards_conformance.md#4-한계)).
