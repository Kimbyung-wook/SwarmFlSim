# 문서 변경 기록

- 브랜치 병합이 매뉴얼(개괄·개발자·사용자, 국문·영문)에 주는 영향을 한 줄씩 적는다. 절차는 [30_doc_plan.md](30_doc_plan.md) §6.2.
- PM이 병합할 때 행을 추가한다. 문서 담당 세션(D)이나 그 장을 처음 쓰는 세션이 반영하고 상태를 바꾼다.
- 새 행은 표 맨 아래에 붙인다. 행을 지우지 않는다.

## 형식

| 열 | 내용 |
|---|---|
| 날짜 | 병합 날짜(YYYY-MM-DD) |
| 커밋 | 병합 커밋(짧은 해시). 병합이 아닌 직접 커밋이면 그 커밋 |
| 관련 ID | DEC·OPN·IMP·TC·CR 등 |
| 내용 | 문서에 영향을 주는 변화 한 줄 |
| 영향 장 | `개괄 §n`, `개발 n`(8장은 `개발 8 <wp>`), `사용자 n`. 국문·영문 공통 |
| 상태 | 아래 상태 값 |
| 처리 | 반영 커밋(상태를 바꾼 세션이 적는다) |

| 상태 | 뜻 |
|---|---|
| 미처리 | 아직 반영하지 않음 |
| 국문 반영 | 국문만 반영, 영문 대기 |
| 완료 | 국문·영문 모두 반영 |
| 보류 | 관련 결정(OPN)이 나지 않아 반영할 내용이 없음. 결정되면 새 행을 추가하고 이 행은 완료로 바꾼다 |
| 해당 없음 | 검토 결과 문서 영향 없음 |

- 영향 장이 여럿인 행은 모든 장이 반영될 때까지 상태를 바꾸지 않는다. 장별로 반영할 때마다 처리 칸에 `<장> 국문 반영 <커밋>` 또는 `<장> 영문 반영 <커밋>`을 덧붙인다. 상태는 마지막 장까지 반영했을 때 바꾼다.

- 기록 시작점은 `ac0a5aa`(DEC-066~069)다. 그 이전 변경은 각 장을 처음 쓸 때 현재 코드를 기준으로 쓰므로 따로 적지 않는다.
- 매뉴얼 본문이 아직 없으므로 아래 초기 행은 모두 "미처리"이고, 해당 장을 처음 쓰는 세션이 반영한다.
